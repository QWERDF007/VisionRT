# 完整改进方案

## 1. 维持的架构约束

VisionRTContracts提供可写DataRef/Owner、类型、工具生命周期与工厂接口，不添加只读/读写属性，不自动复制、不提供COW。VisionRT负责JSON、来源目录、注册表消费、实例生命周期、调度和自身读者的同步。VisionTools自行选择修改、复制或新建输出并负责其共享写协调。

全部新算法采用OpenCV、标准C++及开源表达式组件，不使用HALCON。不让VisionRT依赖InferRT，不引入构建期声明代码生成器。C++手写注册；Python同样提供JSON，由RT按builtin/custom目录选择entry加载。

Image仍为`vector<cv::Mat>` / `list[np.ndarray]`，名称为图像；Array按1至4维嵌套vector/list；ROI为三层double/float容器，复用kind 0–5。已有PythonImages的Storage、capsule、UMatData、BufferLease继续使用，不另建std::any图像桥。可表示布局零像素拷贝，不支持布局由工具显式转换。

## 2. 基础整改先行

先复验已修复的关闭与连线入口，不重复开发。新增异步ReaderDrainCoordinator（名称可按现有代码风格调整），集中跟踪显示、文本、后续点选读者。它仅协调宿主读者，不改变工具的数据权限或算法选择。

操作流程：接收管理意图 → 停止接纳新读者/取消pending → 等在途读者完成回调 → 正确消费或取消信箱 → 归还当前readback token → 执行start/reset/synchronize等续体。close一旦进入不可逆阶段不能被续体重新开放入口。所有完成回调先验证generation和操作序号。

纯YOLO算法回归拆到CPU目标。不要把图像测量和表达式测试再次挂到GPU开关之下。

## 3. 七工具交付路线

| 阶段 | VisionRT | VisionTools | 阶段验收 |
|---|---|---|---|
| M0 基础 | 异步读者排空；目标环境验证Ready/绑定修复 | 独立CPU后处理测试 | 读者未归还不写、不完成，GUI心跳持续 |
| M1 契约与图像 | schema 3、format 4、ROI alignment编辑、类型与消息 | 取图扩展、旋转、亮度、共享几何 | 多图/路径/角度/类型/单位边界正确 |
| M2 逻辑 | 节点级动态端口、公式编辑、guard/Skipped/Blocked/select | 共享受限AST引擎、表达式与条件Python类 | 假支路正式工具不执行，条件错误不走else |
| M3 测量 | 复用现有显示与结果面板 | EdgeProfile、CircleFit、圆和行间距工具 | 标准夹具数值精度与失败分类达标 |
| M4 智能点选 | 最新请求合并、读者租约、上下文、原子参数事务 | 两个隐藏helper，共用正式测量内核 | 悬停不dirty/不读下一帧，陈旧提案零修改 |
| M5 安装验收 | 全链路、保存重开、Once/Loop/Stop/Close | 完整模块、Python依赖与声明包 | 离开开发源码目录仍可运行 |

各阶段是交付顺序，不是乐观工期估算。完整算法、端口和测试条件见[七工具目标规范](七工具目标规范/README.md)。本轮没有降低其中的ROI坐标、异常配对保留、无检出与错误区分等要求。

## 4. 必须同步落实的宿主语义

- 输出名称右键直接为可搜索的下层节点→输入菜单；只接受source.y<target.y，禁同级、自身、上行；名称上下文不绑publication，数据上下文要绑publication。
- Once/Node读回图像与ROI；Loop只发耗时、badge、状态色和轻量时间，不每轮读重数据；Stop后最终读回一次，ACK后completion。
- 底部保持`流程名：xxx ms | 全流程：xxx ms | 已运行：00:02:34:456`。全流程是所有选中flow完成的墙钟，不是各flow相加；elapsed覆盖整个会话及最终收尾。
- 0.02ms节点调用和38ms流程时间不能直接比较；分别记录初始化、准备、调度、转换及读回边界。当前round计时已在readback之前，不应无证据把差值归因于UI。
- 未测阶段为“—”；Skipped为“未执行”；无检出是成功空业务结果，非法参数/算法异常才失败。失败工具消息直出，节点定位留在详情。
- 冻结的Loop画面使用独立展示资源/纹理，不能让QImage继续读取下一轮被原地修改的Mat。

## 5. 架构优化的边界

Contracts ABI原则上无需增加。动态端口是节点配置经唯一物化函数得到，不修改全局工具声明；编译的AST保留在Python工具实例，不在QML另写解析器。算法内核用组合、普通函数和明确值类型，插件边界使用现有多态。

智能点选只增加有实际复用价值的协调器和两个helper，不引入数据库、服务端、全局图像缓存或神经网络训练。每个helper一个在途加一个最新pending，先保证有界与正确，再依据实测优化局部窗口与金字塔。

目标声明/工程升级与新工具包一起交付；旧文件迁移若需要则用明确一次性工具，不能在正式加载路径保留隐式YAML/JSON双解析或猜测字段。实施完将目标端口表转成真实JSON和契约测试事实源，文档保留设计约束与索引。
