# 完整实施方案

## 1. 最终方案

VisionRTContracts 保留 ABI 4 的工具接口、可写 DataRef 和 Owner、基础类型及注册接口。VisionTools 手写 C++ 工具工厂和 Python 类，实现算法、输入检查、结果组装与状态消息，随包提供 JSON。VisionRT 负责解析声明、按来源定位 Python、注册与实例化、节点配置、调度、展示和宿主读者生命周期。

工具声明不生成 C++ 代码；Python 工具也不解析自己的声明 JSON。运行时把节点表达式配置整理成普通初始化参数，不属于构建代码生成。工具返回的业务错误消息原样显示，节点、阶段及堆栈保留在诊断详情中。

| 能力 | 实现位置 | 方案 |
|---|---|---|
| 从文件获取图像 | VisionTools preprocess | 扩展已有 `visionrt.image.read`，增加路径列表、序列读取和明确的游标规则 |
| 旋转图像 | VisionTools preprocess | 新工具 `visiontools.image.rotate`，OpenCV warpAffine，明确像素中心与扩展画布 |
| 调整亮度 | VisionTools preprocess | 新工具 `visiontools.image.brightness`，gain / offset、ROI / mask，相同几何输出 |
| 评估表达式 | VisionTools Python builtin + VisionRT 编辑器 | `visiontools.logic.expression`；共享受限 AST 引擎，节点级动态端口 |
| 条件分支 | VisionTools Python builtin + VisionRT 调度 | `visiontools.logic.branch` 输出两个互斥 Bool；RT 门控节点执行 |
| 测量圆 | VisionTools metrology | `visiontools.measure.circle`，径向卡尺、亚像素边缘、鲁棒几何拟合 |
| 测量行间距 | VisionTools metrology | `visiontools.measure.row_spacing`，投影、边缘配对、宽度 / 间距 / 节距 |
| 智能点选 | VisionRT ImageViewport / PreviewCoordinator + VisionTools metrology | 复用两种测量内核的独立辅助实例，预览与正式运行隔离 |
| 分支合流 | VisionRT host | `visionrt.control.select`，按 Bool 选择同类型输入并传递原 Owner |

不引入 HALCON、混合元组、HTuple、HObject、HALCON ROI handle、脚本化 HALCON 算子、专有图像格式承诺。图像处理和测量不依赖 InferRT。表达式引擎采用 simpleeval 的受限适配层；固定安装版本，保留其许可证，随现有 Python 环境离线打包。是否升级该库属于依赖维护，不由运行时联网决定。

## 2. 与当前代码的差距

这是新功能适配差距，不把未实现的新需求描述为当前缺陷。

| RT `core/Project.h`、`ProjectStorage.cpp` | 工程 format 3，节点输入及输出类型来源 | format 4 的表达式配置、执行门控、select 类型；完整保存及加载诊断 |

既有可写零拷贝、关闭状态机、循环轻量发布是基础，不应为了新工具替换成 `std::any` 或新的所有权系统。关闭Ready入口及Literal闲置source造成的候选/提交差异，已在当前提交修复并完成源码检查，目标环境复验见本轮报告。新增异步读者排空和CPU算法测试拆分为前置优化。YOLO纯填充框问题已用本轮C++探针验证修复；后续测试拆分不混入CPU测量算法实现。

## 3. 模块和代码组织

### VisionRT

在既有 NodeContracts / ProjectEditor 中集中契约物化和编辑事务，不另建平行节点模型库。增加轻量值对象 `ExpressionNodeConfig`、`ExecutionGuard`、`NodeDisposition`。调度继续使用现有 Taskflow；每个节点包装任务在调用正式工具前检查门控。状态统计和节点 UI 从同一个 snapshot 派生。

`PreviewCoordinator` 是值得独立封装的组件：它持有一个在途请求和一个待替换请求、独立工具实例、Owner、上下文及排空状态。AppController 仅转发命令和结果，不继续累积图像算法或另一个线程池。复用现有后台执行设施；需要新的执行线程时只给点选读者一个有界执行通道。

建议新文件：`core/ExpressionConfig.*`、`runtime/ExecutionGate.*`、`runtime/SelectTool.*`、`ui/PreviewCoordinator.*`、`ui/qml/ExpressionEditor.qml`。文件是否拆分以职责和复用为准，不为每个小函数新建类。

### VisionTools

`src/preprocess` 增加 RotateTool、BrightnessTool；`src/metrology` 增加 CircleTool、RowSpacingTool、AssistCircleTool、AssistRowSpacingTool 及模块注册。共享 `EdgeProfile`、`CircleFit`、`GeometryTransform` 为普通 C++ 算法组件，工具类仅承担接口转换与状态。辅助工具和正式工具调用同一算法内核。

Python 目录建议 `python/builtin/logic/common/`、`expression/tool.py`、`branch/tool.py`；使用现有按包路径加载机制组织包内导入，避免修改进程全局 sys.path 或同名 `tool` 模块相互覆盖。具体文件路径在声明 entry 中唯一指定。

### C++ 设计取舍

- 多态仅用于既有 `IToolInstance`、工厂及确有替换需求的外部边界；算法内部用组合和普通函数，不设计深继承体系。
- 用 `enum class` 表示极性、读取模式、画布模式、终态；在 JSON/Values 边界把字符串转成枚举，算法循环内不反复比较字符串。
- RAII 管理计时、buffer、预览租约、工具 release；资源句柄默认 move-only，禁止复制不清楚的取消令牌。
- `std::span` 用于借用采样序列，`std::optional` 表示缺省参数或测量结果，`std::variant` 沿用 Contracts 值模型。不能让 span 跨越其 Owner 生命周期。
- 模板用于现有 DataRef、数组 rank/dtype 分派及确有必要的像素算术；不要用模板生成声明或把整个算法写成编译期 DSL。
- 图像变换借助 OpenCV 矢量化实现；性能热点经测量后优化，避免为七个工具创建通用工作流框架、缓存数据库或复杂插件协议。

## 4. 阶段交付

1. **基础契约**：修复已确认入口/绑定问题，落地类型、schema、节点契约、事务和测试夹具。
2. **图像工具**：取图、旋转、亮度；建立多图、坐标、路径及显式所有权的端到端例子。
3. **逻辑工具**：表达式公共引擎、动态端口、门控、合流、跨流程跳过传播。
4. **测量工具**：共享边缘内核、圆与行间距，先以合成图确定数值行为，再用用户实际图验证。
5. **智能点选**：辅助工具、悬停读者、学习与原子提交；接入 Stop/Reset/Close 和循环模式。
6. **交付验收**：有针对性的契约测试、完整集成、实际安装态和一次全量回归；完成后才发布安装包。

没有真实样本时可以验收接口和合成基准，不能宣称实际产品缺陷检测率、任意材质的测量精度或商用软件等效性能。安装态证据需记录实际提交、工具包和依赖版本，本包不复用之前的 76/76 作为新增功能通过证据。
