## 推荐端到端工程

**工程一：图像采集与处理。** directory sequence → rotate → brightness → 显示。循环3次后停机；验证路径/索引、角度矩阵、每轮仅轻量UI、最后显示正确图像。中间坏图不得推进索引。点击候选预览不调用读图。

**工程二：测量与分支。** 图像读取 → 圆测量 → expression（从指定图像的 radius_px 取数组，判断非空且范围合格）→ branch → 两个有执行计数的处理支路 → select → 保存或下游检测。依次输入合格、空检测、不合格、非法公式；非法公式不走false业务支路。

**工程三：引脚行检测。** 图像读取 → row_spacing → expression 分别检查 width_px 与 gap_px → branch。夹具包含一个超宽物体和一个漏边；确认原始配对/间隙仍可诊断，不因筛选而丢失异常。

**工程四：智能点选生命周期。** Python生成图像 → C++裁剪视图 → 单次显示 → 悬停/学习 → Reset/Close；外部额外保留一个cv::Mat。先验证内部helper不阻止进入AwaitOwners，再释放外部Mat验证自动关闭，不能人工调用reset绕过要测的关窗路径。

## 时间与并发的证明方式

不要只 `sleep(50ms)` 后断言一次。关键 barrier 用测试门闩控制 worker 进入/退出阶段，以有界轮询断言整个等待窗口内 start 被拒、没有新执行、没有completion；再释放读者并确认正常推进。超时用于让失败有限退出，不代替事件序数证明。

记录至少 `sessionAccepted, roundSubmit, perFlowComplete, allFlowsComplete, readbackBegin, readbackAck, completion`。例如两flow各约20/30ms并行执行时，全流程接近包含调度开销的墙钟30ms而非50ms；测试不把操作系统调度误差设为不合理的固定精确值。人为延长UI读回应增加elapsed而不覆盖已经记录的roundMs。

内存稳定性以预热后趋势、存活Owner/任务数为主，不要求进程RSS每轮回到同一点。循环至少覆盖1000轮；重资源输出大小、硬件、线程数、图像数写入报告。UI预览80ms目标和数值0.25px目标都要注明具体夹具，未达到时据实整改。

## 发布门槛

接口/生命周期/错误路径/安装态为硬门槛。测量在已定义标准夹具上应达标，真实业务样本缺失则只可发布为已通过合成验收的工具，不宣称生产测量效果完成。所有目标声明、Python依赖和C++模块必须随同一工具包交付；缺依赖不能用生产打包的 allow-missing-dependencies 掩盖。
