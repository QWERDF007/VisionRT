# 完整改进方案

## 架构与职责

Contracts：IToolInstance、ToolStatus、工厂注册协议、类型与可写DataRef/owner；不依赖Qt/Python/JSON解析，不包含渲染或算法策略。

VisionTools：C++ final具体工具实现虚接口、手写工厂；Python函数/类随附JSON；手工拆装输入输出，内部使用算法/InferRT。选择原地修改、显式复制或新输出并自行协调共享写。RT不关心推理框架内部细节。

VisionRT：Qt JSON发现/编辑/保存/输出；模块与Python加载、注册表、节点实例、流程调度、所有权传递和UI。核心规则集中复用，界面仅表达规则。图像、ROI、长文本读取由运行阶段控制，不往数据添加只读/读写属性。

## 类型和文件

| 语义 | C++ | Python |
|---|---|---|
| 图像 | vector<cv::Mat> | list[np.ndarray] |
| 一维数组 | vector<T> | list[T] |
| N维数组 | N层vector<T> | N层list[T] |
| ROI | vector<vector<vector<double>>> | list[list[list[float]]] |

ROI按图像索引→ROI列表→[type_code,数据…]，首值为具体ROI种类，数据格式沿统一ROI协议。Python无double内建名称，float对应这里的double。Image唯一类型，不称图像批次；Array dtype/rank完整保留，列表转换不是零拷贝。

工具声明、module_index、工程、复杂参数编辑与输出文本全JSON；Python通过kind与来源根找到代码，不扫描.py猜工具、不要求工具解析JSON。builtin/custom各自声明根及Python代码根，首次initialize惰性导入，显式Idle刷新。模块目录、路径、依赖沿现有正确实现，不加数据库/哈希/生成器。

## 优先收敛四个内部组件

1. **连接规则**：以ProjectEditor核心规则为唯一入口，统一源/目标存在、同flow、严格更上行、TypeSpec兼容及有效绑定模式。候选、提交、加载诊断和执行前调用同一规则。无须创建通用规则引擎。
2. **运行时钟**：收拢start/finish、round/flow测量与缓存身份；GUI只消费快照和持续elapsed。不把多个double散在控制器各处分支更新。
3. **显示调度**：复用既有DisplayConverter与readback，封装单次/循环/最终读取行为。运行中数据冻结的是UI缓存，新业务Image/ROI仍照常计算。
4. **Python收尾**：停止接收工作→收尾调用与内部引用→外部owner预检→就绪后finalize；借助现有runtime/storage扩展完整生命周期，不新增通用线程池。

这些组件优先是具体类/值类型与纯函数，只有真实多实现边界才用虚接口。现有AppController PImpl不够约束共享成员访问，新增职责封装要实际减少外部可改状态，不能只是拆更多cpp。

## 单次与循环

单次结束：所有flow执行完成，记录全流程；安全生成当前可见工具图像/ROI/预览，隐藏工具保留最后结果，Idle切换按需显示。每个已执行工具都可正常查看。

循环：只发布工具耗时、badge、状态颜色、简短message、flow耗时和已运行；暂停新图像转换、ROI几何生成、业务纹理上传和大文本格式化。保留独立显示缓存；切到无缓存目标保持空白，不读正在变化的结果。循环不建立每轮重资源readback，不等待GUI ACK。

停止：不启动下一轮；等当前不可取消调用/工具后台写入结束；安全刷新最终可见图像与ROI；完成必要收尾后固定已运行。隐藏工具后来查看不重新启动时钟。窗口关闭可跳过无意义视觉刷新但不能跳过真实任务收尾。循环内禁用重资源导出/ROI编辑；轻量诊断仍可用。

## 底部三项

`流程名：12.35 ms | 全流程：17.80 ms | 已运行：00:02:34:456`

- 流程名：当前选中flow实际名称及其最新有效完成耗时。
- 全流程：本轮开始准备/提交之前，到全部参与flow完成收集之后的单调墙钟差；不sum、不max、不计最终UI读回。首次会话准备若在轮外单独记录，已运行必须覆盖。
- 已运行：接受本次启动至实际必要收尾完成。运行中now-start，结束后finish-start，循环不停累加；不累加round/flow，不按UI tick计数。小时不按24取模。

未执行显示— ms，已运行初始00:00:00:000；0与Missing不同。换工程清空计时，切flow按ID读取；同工程新会话elapsed归零，保留上一轮完成值时不能混淆session。所有事件带工程代次/会话/轮身份。

## 菜单与连接

输出名称右键直接带搜索的“下层工具→兼容输入”级联菜单，名称区无查看/复制/关联已有中间项；数据区保留查看复制。中文类型统一，普通tooltip不显示机器ID。已连接当前输出的项勾选去重，占用项不能静默替换。声明级配置不依赖执行结果publication。

同级/反向/自连接禁止，以GridPoint.y为逻辑层级：source.y < target.y；允许跨多层及多分支。同flow普通输入手动值或上级输出；Image手动内容受既有类型约束。跨flow继续显式Receiver机制。

移动在临时候选布局一次验证后提交；非法移动整批回滚。加载旧非法边保留诊断可修复、禁止执行，不偷偷删边。执行计划必须重新验证，不能信任菜单曾过滤。

## 零拷贝与所有权

保留显式集中桥接、Capsule及ImageStorage/UMatData。C++导出base锚定真实像素owner；Python导入仅创建Mat头、UMatData锚定底层存储，Mat浅拷贝/ROI继续保活。回环复用存储锚点但取当前视图shape/stride/dtype/地址，不能直接返回原Mat。

支持CPU H×W/H×W×C和Mat可表达的行padding/ROI；dtype、有效轴stride、标量对齐、尺寸/跨度溢出/范围均校验。长度1轴无意义stride规范化。无forcecast、无自动ascontiguousarray，无只读属性或COW。遇到实际不可写/无法表达数组明确拒绝，由工具主动处理。

外部buffer若需活跃租约才稳定，则保留RAII Py_buffer到最后一个Mat视图释放并在GIL下Release，或不接受该分支。解释器必须活过所有Python锚点和释放回调；关闭检查要冻结新引用并覆盖实例/调用/外部owner，不仅暴露一个计数查询。

## 界面文字

有效ToolStatus.message在状态值、节点和普通tooltip原样显示，detail单独诊断。空文本沿既有Contracts规则补默认值。中文displayTypeName独立于机器type/dtype/rank，覆盖输入、输出、绑定、关系和端口编辑器。保留当前界面布局。

## 实施顺序

先补连接加载/执行约束与循环读回；接持续时钟、缓存代次和停止最终显示。随后统一菜单/类型/消息。并行完善Python关闭与租约。最后执行真实Qt/原生桥接/安装态验收，验证后再做有测量依据的性能优化；不以模板/继承数量作为代码质量指标。
