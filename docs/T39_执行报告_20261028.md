## 3. 未完成项与原因

### 3.1 T39-15 无 Qt 运行时独立路线（P3，未启动）

未做的原因：

1. **方案本身定为独立后续目标**。S39-14 明确“无 Qt 为独立路线，不作为 T39-16 的前置”，优先级 P3。本轮目标是让 T39-01..14 的验收全绿，把它塞进来会推迟可交付的收尾。
2. **必须先有纯 std 的模型层，才谈得上拆 Qt**。当前 `Project.h`、`ValueJson.h`、`PluginLoader`/`PythonRuntime` 的 Qt 依赖是三处独立耦合（值模型、JSON 编解码、平台加载），拆分顺序被依赖关系锁死：错误与值模型 → 无 Qt probe → 再迁 JSON adapter。跳过前一步直接拆 JSON，只会得到“两套模型并存”。
3. **与 T39-08 同批做会让失败无法归因**。错误码迁移已经改了 `src/` 全部失败路径；再叠加依赖边界调整，测试红了分不清是码值错还是链接错。
4. **缺少证据载体**。这条工单的验收物是 `no-Qt probe` + `dumpbin /dependents`，属于新增构建目标；仓库目前没有这个探针，等于要在收尾批次里新开一条构建链。

建议的首个切片（下一轮可直接开工）：`core/Error.h` + 值模型抽成不依赖 Qt 的静态库 → 加只链接它的 probe → `dumpbin /dependents` 证明无 `Qt6*.dll` → 再把 `Project.h`/`ValueJson.h` 的 Qt JSON 迁到 adapter。

### 3.2 T39-16 跨仓发布验收与证据交付（P2，部分完成）

已具备的分项证据：真实 profile 出包（cpu / rtx40-build）、安装隔离 PATH（`installed_pipeline_contract`）、GPU 实测（`gpu_tools_contract`，RTX 4060，208 s，build_wts + 推理两阶段）。

缺的是“一次性发布”的四件事，各自原因不同：

| 缺口 | 原因 |
| --- | --- |
| 一次全量发布运行 | 需要一个干净 build 目录把 `backend/bridge/ui/sdk/installed/package/gpu` 全组跑完；当前 `package` 组必红（见 3.3），全量跑不出绿结论，只能分组取证 |
| 源码与依赖来源留证 | 方案未指定载体（清单/哈希/构建信息汇总），本轮优先保证代码与测试行为，未额外生成 provenance 汇总；`build_info.json` 只覆盖单仓构建时间 |
| 性能对比 | `build/evidence/runtime_benchmark.json` 是历史基准，不是本轮改造前后的 A/B；做 A/B 需要保留改造前二进制并按同一模型、同一机器重跑 500 轮，本轮没有保留基线 |
| Debug 配置实测 | `$<TARGET_FILE>` 表达式本身与配置无关，但只实测了 Release；Debug 需要重配构建目录并重新出包，属于额外一轮完整构建 |

结论：T39-16 不应按“已完成”记账，它是**一次发布动作**，不是又一轮代码修改。

### 3.3 已知失败：`build_incremental_contract`（环境阻塞，非代码缺陷）

`ctest -R build_incremental_contract` → Failed（12.3 s）。复跑输出显示 `tools/build.cmd` → `vcvars64.bat` → `reg.exe` 被当前沙箱安全策略拦截（Program Blacklist），编译器环境变量没建立，CMake 在 `project()` 处报“will not be able to correctly generate this project”。

这不是脚本参数拆分缺陷（此前 WORKLOG 的推测），也不是本轮改动引入：改用直接导出 `INCLUDE`/`LIB` 后同一构建树可以完整编译（VisionRT、VisionTools 增量构建均 0 错误）。需要在**非受限终端**复跑一次才能给出绿结论。

### 3.4 未复跑的组

`sdk`、`package`、`gpu` 本轮未复跑：它们验证的是契约子工程、出包链路与推理链路，本轮提交未触及这些路径（`package` 组另见 3.3）。报告不把上一轮的结论当作本轮证据。

## 5. 遗留与建议

1. **先补 T39-16 的三块证据**：干净 build 的全组运行、provenance 汇总（子模块 commit + 依赖版本 + 包清单哈希）、改造前后 500 轮 A/B。三者都不改代码，只补流程。
2. **再开 T39-15 首个切片**（纯 std 模型 + no-Qt probe），按 3.1 的顺序做，避免与错误码语义再次耦合。
3. **仓库卫生**：Contracts 子模块里仍有一条指向 `F:/Projects/VisionRTSDK` 的 `local` remote，该路径已不存在，`git push local` 会直接失败；日常只用 `origin`，建议后续清掉这条配置。
4. **路径策略已成对断言**：`project_storage_contract` 的“普通保存保留字面量”与 `ui_project_paths_contract` 的“另存后重定位”是一对，改任一侧必须同时改另一侧，否则会在“只改一处”时得到假绿。
