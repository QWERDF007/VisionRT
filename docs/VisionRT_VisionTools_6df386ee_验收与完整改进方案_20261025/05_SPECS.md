# 实施规范 Specs

## S-E01：关闭终态和入口一致性

状态来源为 ClosePhase。关闭期定义覆盖 Resetting、AwaitOwners、Ready；若兼容保留 closing bool，统一谓词必须同时消费二者，不能由调用方自行拼接不同表达式。

| 阶段 | 保存 | 编辑/运行/刷新/新读回 | 允许事项 |
|---|---|---|---|
| None，无 pending | 按现有条件允许 | 按 Idle/运行条件允许 | 常规业务 |
| None，未保存决定 | 按明确保存选择允许 | 拒绝冲突业务 | 保存、丢弃、取消决定 |
| Resetting | 拒绝 | 拒绝 | 停止、排空、消费已提交完成通知 |
| AwaitOwners | 拒绝 | 拒绝 | 事件循环、Owner 归还检查、必要状态显示 |
| Ready | 拒绝 | 拒绝 | 发一次 closeReady、对象销毁 |

Runtime Idle 不是解除 ClosePhase 的条件。isClosing 属性和实际后端门控必须一致。Ready 状态下 closeReady/closingChanged 的同步槽重入也不得提交工作。重复关窗不重复发信号；取消未保存决定只在未进入不可逆阶段时生效。

## S-E02：绑定的有效性和占用

`effectiveSource(binding)` 仅在 Upstream 且 source 存在时有值。source.y<target.y、同一 flow、存在的端口、相容类型等仍由 validateBinding 检查。

| 目标状态 | 菜单 | 提交连接 |
|---|---|---|
| Literal，无草稿 | 可连接 | 成功，切 Upstream |
| Literal，有旧 source | 可连接 | 成功，用用户新选择更新来源 |
| Upstream，无 source | 可连接 | 成功 |
| Upstream，等于当前输出 | 勾选 | 保持/显式解绑，不能重复建边 |
| Upstream，其他输出 | 占用禁用 | 拒绝，不能静默覆盖 |
| 同级/向上/自身/类型错 | 不作为合法候选 | 后端拒绝 |

current candidate API、旧兼容查询 API、bindFreeInput 必须消费相同占用状态。名称上下文不含 publication；结果上下文含 publication。不得为了修草稿问题放宽层级规则。

## S-E03：YOLO 有效候选与最大检测数

网络坐标候选在参与 NMS 前，必须能映射为原图内正面积框；完全位于 padding 或裁剪后面积为零者不消耗 maximum，也不能抑制其他有效候选。可选 raw trace 仍可保留它们。

本次修复不改变：类别隔离、置信阈值、score/candidateIndex 排序、有效框的网络坐标 IoU 计算、已有输出 ROI 编码及顺序。先排除无效候选，再完成 NMS 和 maximum 限制；最终源坐标框仍合法。

如果后续采用裁剪后原图坐标 NMS，应单独声明算法变更，并重新核对参考数据，不纳入本次最小修复。

## S-E04：证据归属

源码验收基于固定提交；每份执行日志标明源提交、构建配置、命令、返回码和时间。安装态测试必须使用该构建产生的包、实际部署 tools-package 和解释器。过去的 76/76、可执行文件哈希、文件数量和 -v 只能证明对应记录，不能自动转移到新提交。

无需建立新数据库/签名平台；现有记录脚本或一份文本/JSON 即可。源审查、实际独立运行、用户报告三类证据不可混写。

## S-E05：轻量 UI 和时间

Loop 不产生逐轮重资源 token，不读新像素、遍历 ROI 或序列化大结果。允许已有静态画面保持，轻量状态按既有节奏更新。停止后执行一次最终读回并 ACK，Stop 不提前解除 ACK 屏障。

增量优化不得丢失 active、错误、generation/session 切换、最终状态与完成通知。底部三个时间分别使用选中 flow 墙钟、一轮所有 flow 墙钟、会话单调时长。未测阶段为 —，不能用 0 假装实测；真实 0 合法。

## S-E06：查询和缓存边界

节点/端口索引只针对结构性数据，按查询期或明确结构版本有效。不得缓存可写数据的“已验证”“不可变”等状态。改变实现方式不得改变 source.y<target.y、Receiver 依赖、加载诊断、移动/粘贴行为。

消除 O(U×N) 重复查找可先使用一次 poll 的 NodeId 集合。是否引入持久索引或增量 runtime updates，必须由基准决定。

## S-E07：CPU 工具优化的输出等价

优化前后保持类型、输出顺序、阈值、ROI 坐标与像素中心规则、成功/失败和 Missing 语义。存储方式属于工具契约：identity、显式 clone、裁剪视图、带掩码新输出不可在“加速”中混换。

本次调用内临时容量可复用；跨调用复用已发布输出时，工具必须自己证明所有引用和并发行为安全，宿主不提供隐式 COW。空图像列表的已有工具专属约定保留，若统一需另立兼容性变更。

## S-E08：推理资源与指标

State 拥有模型/会话/stream/缓冲。返回前输出就绪，release 在销毁资源前完成流内工作。CPU enqueue、GPU 执行、拷贝、CPU 后处理分别度量，嵌套阶段不重复累加到总耗时。

最大 logit 只计算一次 sigmoid 是待验证候选，不承诺与当前 float 饱和后的类别平分完全等价。优化须固定 tie 行为、阈值边界和模型输出布局。

## S-E09：Python 示例的可写语义

Image 为 list[np.ndarray]，输出结构遵循 JSON，不新增 readonly/write/readWrite 字段。copy/inplace 由工具参数和实现选择。若修改 image_add 示例，先检查整个输入再写，明确仍不承诺计算过程中任意异常的完整事务回滚。临时数组优化由工具承担，不变更 RT 桥接策略。

## S-E10：工程和 C++ 维护

模板只用于减少真实类型/工厂重复；不添加运行时接口生成器。内部值类型/状态函数优先于额外虚类。兼容计时字段收敛必须逐一迁移读写位置，不允许半迁移双写产生不同口径。构建配置分目录时同步脚本和包装输入，不修改工具 JSON 业务 schema。

## S-E11：持续保持的总体契约

- JSON 全覆盖，工厂手写注册，工具实现与声明解析分离。
- Contracts 提供可写载体/Owner；RT 保活与自己的读者协调；Tools 承担修改策略及共享写协调。
- Image 唯一类型；Array 为嵌套 vector/list、当前 rank 1～4；ROI 三层且最内层首项为 kind。
- 像素桥接不隐式复制，不强制只读，不把 ndarray 返回理解为自动将内存所有权转移给 C++。
- 工具错误 message 原样展示；普通端口名和类型用中文；名称菜单直接下层候选。

该规范包含本轮修复与应保持的已实现行为。不是要求对所有已通过项重新开发，也不是要求全部可选优化立即上线。
