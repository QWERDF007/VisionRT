## 2. 必须保持的集成契约

| 场景 | 检查点 |
|---|---|
| Once / Node + Stop | reader 未 ACK 前无 completion/Idle，新 start 拒绝 |
| Loop 连跑 | 无每轮图像/ROI/text 转换读回，轻量状态持续变化 |
| Loop Stop | 仅最终读回，读者 ACK 后收尾；最终状态不丢 |
| Reset / Close + 慢 release | GUI 事件循环持续，协调器释放，内部 owner 先清 |
| 外部 Python 图像 owner | 保持 AwaitOwners；归还后 Ready，解释器最后销毁 |
| drain 重入 | 外层 draining 状态不提前复原，结果恰好交付一次 |
| 零拷贝跨语言 | 指针关系、合法正行步长、切片尺寸、父对象删除、最后释放 |
| 不支持布局 | 负步长/广播/转置等明确拒绝，不暗中拷贝 |
| 工程 JSON | 手动输入、闲置来源、活动边、Int64、ROI 保存重开一致 |
| 状态与类型 | 工具 message 原文；中文类型；系统端口机器 ID 不当普通名称 |
| 菜单上下文 | 结果 publication 变化不破坏名称菜单；结构/项目变化使旧上下文失效 |
| 时间 | 并行 flows 的全流程墙钟独立实测；Loop 已运行累计，未测 — |

沿用已有契约测试；只给本次实际缺口增加针对性用例。不要为每个 getter 或换名字写镜像实现测试。

## 3. 性能测量设计

| 基准 | 数据集 | 观察指标 | 决策用途 |
|---|---|---|---|
| UI 轻量更新 | 10/100/1000 节点，单/多 flow，Once/Loop | poll control 锁时长、GUI poll p50/p95、帧卡顿、行构造次数 | 是否需要 ID 索引和增量行 |
| 候选菜单 | 节点数量与输入/输出数量分开变化，含 Literal 草稿/活动占用 | 菜单构造 p50/p95、validate 查找次数 | 局部索引和去重复查环 |
| 图像桥接 | 小图、1080p、4K，1/多图，正行步长 ROI、Python 新数组 | 像素复制次数/地址、桥接耗时、Owner 释放次数 | 验证无隐式像素复制，非全链路零分配 |
| Projection/Crop | 图尺寸、ROI 面积/角度、横纵方向 | 算法 p50/p95、mask 构造、额外内存 | 向量化/扫描线收益 |
| Filter | 检测数 D 与 allowed 大小 A | 耗时、分配量、输出相同 | 决定线性/排序/哈希分界 |
| YOLO | 固定模型、GPU、精度、640 输入、原图宽高比与图像数 | 首次/稳态分离；CPU/GPU/传输/后处理，吞吐与显存 | 哪一阶段值得优化 |
| Python image_add | copy/inplace、0/254/255、连续/合法视图 | 输出与别名语义、临时内存峰值、耗时 | 是否采用 out 参数 |

同机同配置、固定输入、记录 warm-up 与样本数。可先取 30 次预热、200 次稳态样本作为起点；若模型/IO 特性不同调整并记录，不把该数当普遍定律。报告 p50/p95 与峰值内存，不只挑最小值。性能阈值在首份真实基线后制定；本报告没有虚构加速比例。

“工具 0.02 ms，流程 38 ms”不能单靠数值断定就是 UI。应区分工具边界、调度/队列、首次初始化、整轮、多 flow、读回与会话边界，再用上述测量定位。Loop 门控消除重渲染后，剩余差值仍可能来自宿主工作或线程调度。

## 4. Windows 安装验收

在用户既有构建环境执行，并保存真实日志。示意顺序为构建→CTest→严格打包→安装态测试→实际工作台运行/关闭。继续使用 D:\tmp 作为临时目录，E:\Softwares\VisionRT 为部署路径；工具包来自同次 VisionTools 构建。

```powershell
$env:TEMP = 'D:\tmp'
$env:TMP = 'D:\tmp'
tools\build.cmd ctest --test-dir build --output-on-failure
python tools/package_app.py --install-dir E:/Softwares/VisionRT --tools-package D:/Project/VisionTools/dist/VisionTools.zip --force-clean
& 'E:\Softwares\VisionRT\VisionRT.exe' -v
.\build\bin\installed_pipeline_contract.exe 'E:\Softwares\VisionRT\tools-package'
.\build\bin\installed_python_author_contract.exe 'E:\Softwares\VisionRT\tools-package'
```

命令仅沿用当前路径示例，执行前先完成当前配置构建；若按 E10 改了 binaryDir，命令须相应更新。--force-clean 应继续仅作用于已确认的专用安装目录。

实际工作台运行时记录进程可执行文件路径、已加载 python312.dll 路径与 NumPy 来源。解释器来源要从实际应用会话观测，不是另起系统 python 打印 sys.path。不要仅凭 2758 文件、截图或 -v 宣布完整生产通过。
