# 05: 平台节点按工具包声明绑定并收敛工具列表

**What to build:** 已有结果接收等平台执行能力保留在宿主，但可见工具及其类型由安装包声明决定；用户不再受宿主固定工具 ID、类型后缀清单和内置目录扫描影响。

**Blocked by:** [03：领域 DLL 经工具 ZIP 部署到宿主执行](03-zip-deployment.md)。

**Status:** completed — 已完成并通过验收测试。

**Specification:** [D-04、D-07、D-08、D-13；US-05、US-19 至 US-23、US-33；T-05](../spec.md)。

- [x] 平台节点声明由工具库交付，经 host_binding 选择宿主已有执行器，输入输出类型来自解析后的声明。
- [x] 不维护具体工具 ID 或后缀数组；改变包中接收节点的声明后，工作台呈现和执行遵循元数据，不需要为新工具身份增加宿主名单项。
- [x] 真实跨流程接收保留其超时、错误和结果类型行为；未知 host_binding 明确不可用，不注册默认实现。
- [x] 生产发现只读取安装包索引，移除多根目录兜底和捎带宿主算法声明的发布路径；测试夹具不混入工具列表。
- [x] 无包时工作台可启动并显示空工具状态；未索引声明不出现，包错误和缺失工程工具保留诊断。
- [x] 不把宿主调度能力迁移成新 DLL，也不新增服务定位或通用能力框架。
- [x] 先补真实接收节点、列表变化及无包状态测试，再切换生产发现与执行路径，删除已替代实现。

**验证演示：** 只更换工具包声明，即可改变一个接收节点的可见身份及属性并完成真实跨流程接收；移除包后列表为空，放回旧宿主声明目录不会补出工具。
