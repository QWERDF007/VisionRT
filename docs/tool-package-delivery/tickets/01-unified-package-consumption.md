# 01: 统一真实工具包读取与消费

**What to build:** 真实工具目录包通过 SDK 的同一读取与校验语义进入校验器和宿主，用户仍能看到并运行原有工具。先完成有可观察行为的预重构，让后续 ZIP 和索引变更无需在各端重复改解析逻辑。

**Blocked by:** None.

**Status:** completed — 验收范围与证据见[验收报告](../../VisionRT-VisionTools-验收评估报告.md)。

**Specification:** [D-01、D-03；US-11、US-16、US-24；T-02、T-03](../spec.md)。

- [x] SDK 的强类型工具包描述包含最终索引、解析后的声明和实现关联，现有校验 CLI 与宿主消费它，不各自重写包语义。
- [x] 不改变当前有效目录包的可观察行为；以真实包中至少两个同领域工具验证显示和执行，不以 mock 工厂替代 DLL；读取与校验不按计算后端或样例工具清单限制有效包。
- [x] 缺声明、错引用或坏索引经 CLI 和宿主得到一致诊断，不依赖源码中的另一份声明救场。
- [x] 本片不提前新增 ZIP、发布格式、第二套注册表或未来安装框架；旧的重复解析逻辑在切换调用方后删除。
- [x] 先增加覆盖真实校验器与运行时下一层依赖的失败测试，再完成实现；保留已有有效包的回归证据。
- [x] 涉及 SDK 锁定版本的消费者同步更新，本片完成时相关目标可构建并可独立验收。

**验证演示：** 对同一个现有可运行目录包进行校验及宿主消费，以该包工具的固定输入断言两个工具结果；再移除一份声明，观察两个入口均拒绝该无效包。记录样例的实际运行前提，不将其推广为协议限制。
