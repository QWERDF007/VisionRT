# 03: 领域 DLL 经工具 ZIP 部署到宿主执行

**What to build:** 工具库普通构建仍输出领域 DLL；显式打包输出一个 ZIP 和同源索引，宿主部署操作消费 ZIP，用户从安装元数据看到并运行其中 C++ 工具。实现第一条完整交付链，而非只新增压缩命令。

**Blocked by:** [01：统一真实工具包读取与消费](01-unified-package-consumption.md)。

**Status:** completed — 验收范围与证据见[验收报告](../../VisionRT-VisionTools-验收评估报告.md)。

**Specification:** [D-01 至 D-07、D-13；US-01 至 US-12、US-15、US-19；T-01、T-02、T-03、T-09](../spec.md)。

- [x] 两仓普通构建仍输出常规 EXE/DLL，不自动打包；宿主构建不要求工具源码、ZIP 或工具安装存在。
- [x] 同一领域至少两个 C++ 工具共用 DLL；按真实构建产物打包，不创建每工具 DLL 或空领域库。
- [x] 最终索引采用规格的 version 2 和 tool_id 身份；包括 Python/宿主绑定所需的明确结构与合法组合校验，但不提前注册未实现的执行器。
- [x] 增加一个 tool_id 与 registry_name 不同的真实工具用例，部署后仍正确创建和执行，证明二者没有混用。
- [x] ZIP 按实际构建产物和声明收集最终索引、声明、库及必要依赖和资源，外置索引逐字节一致；不强制按计算后端分包或限定工具组合，构建中间索引不能直接冒充发行索引。
- [x] 部署入口消费 ZIP，经临时解包和同一 SDK 读取校验后安装；工作台显示安装包的 C++ 工具并输出固定数值结果。
- [x] 错版本、重复身份和缺引用明确失败；同步更新三仓消费者及锁定 SDK，不保留旧索引格式或旧外部目录部署入口。
- [x] 先补打包、部署、索引身份与真实执行的局部失败测试，再实现；可演示离开工具源码目录消费该 ZIP。

**验证演示：** 构建并打包现有可运行领域库及必要依赖和资源，把 ZIP 交给独立构建的宿主部署操作，在新目录打开工具列表并执行两个工具，不使用开发源码或目录扫描兜底；样例后端不成为打包或部署条件。
