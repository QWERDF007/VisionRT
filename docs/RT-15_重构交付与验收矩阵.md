## 2. 宿主单源配置与交接规范 (RT-11, RT-13 / VR4-06)

为消除配置分叉与历史包袱，本仓库实施统一单源配置：
1. **依赖与路径单源**：[`tools/dependencies.yaml`](../tools/dependencies.yaml) 与 [`CMakeLists.txt`](../CMakeLists.txt) 定义 Qt、OpenCV、Python 的依赖发现与打包清单，修改一处即可作用于 CMake 配置与分发。
2. **构建与打包唯一入口**：[`tools/build.cmd`](../tools/build.cmd) 提供一键编译（`--build`）、全量测试（`--test`）及分发打包（`--package <dir>`）；[`tools/package_app.py`](../tools/package_app.py) 遵循直接构建与全新安装策略，并提供 `--test-verify` 自检测试。
3. **视觉主题单一真相源 (SSOT)**：通用控件全面回归 `quickui::quickui` 原生样式；业务四态状态色（灰、蓝、绿、红）与状态徽标在 [`src/ui/Theme.h`](../src/ui/Theme.h) 与 [`src/ui/qml/NodeDelegate.qml`](../src/ui/qml/NodeDelegate.qml) 统一定义，无外部冗余复述。
4. **动态插件加载单一真相源**：[`src/plugins/PluginLoader.h`](../src/plugins/PluginLoader.h) 与 [`src/sdk/include/visionrt/sdk/Module.h`](../src/sdk/include/visionrt/sdk/Module.h) 统一规范 C++ 插件动态加载与 `visiontoolsModuleApi` 导出接口，统一以 `module_index.yml` 为唯一模块映射契约，杜绝 JSON/XML 多格式分叉。
5. **文档入口单一真相源**：[`docs/README.md`](README.md) 为系统设计规范与接口索引唯一入口。

## 4. 核心性能与交互回归实测数据 (VR4-04, VR4-05)

### 4.1 200 节点拓扑图执行延迟 (A15)
- **拓扑结构**：200 个串联加法节点构成的 DAG 拓扑，包含 5 轮预热 + 30 轮连续实测。
- **分位数测量结果**：
  - **p50**: `15.37 ms`
  - **p95**: `16.17 ms`
  - **p99**: `16.38 ms`
- **验收结论**：调度执行延迟 p95 远优于目标红线（目标 ≤ 100ms），**实测通过**。

### 4.2 真实 10 张 4K 图像零拷贝扇出与原子复制点双探针 (B05 / VR4-05)
- **输入规模**：10 张 4K 图像批次（3840 × 2160 × 3 通道，单批次原始像素 ~248.8 MB）。
- **C++ 扇出分支**：100 个消费者分支并行读取上游 `ImageBatch`。
- **边载荷复制验证**：`C++ payload copies per edge = 0`，**实测通过**。
- **DisplayConverter 饱和高水位**：并发提交 5 个批次请求，断言在途 `in-flight <= 1`，待办队列高水位 `pending <= 1`，高水位观测值为 `1`，**实测通过**。
- **Python 单次叶输出原子复制点探针**（`VISIONRT_TEST_PROBES` 宏隔离）：
  - 连续 ImageBatch 输入：`copy count = 10`（恰好 1 次/叶，目标 <= 1/叶，**实测通过**）；
  - 非连续 ImageBatch 输入（步长切片）：`copy count = 10`（恰好 1 次/叶，目标 <= 1/叶，**实测通过**）；
  - Dense NumericArray 输入：`copy count = 1`（恰好 1 次/叶，目标 <= 1/叶，**实测通过**）；
  - 非法/畸变输入测试：复制计数保持为 0，探针只在成功构造并执行数据拷贝后递增，**实测通过**。

### 4.3 循环压力与内存稳定性监测 (VR4-05)
- **循环轮次**：连续执行 50 轮真实 ImageBatch + DisplayConverter + C++ 节点循环，实时采集 Windows Process Working Set (RSS)。
- **RSS 内存曲线**：
  - Initial: `44,468 KB`
  - Round 25: `48,040 KB`
  - Round 50: `48,040 KB`
  - Steady: `48,040 KB`
  - Peak: `48,040 KB`
  - AfterReset: `48,040 KB` (进入稳态后漂移 0 KB，增长 < 10 MB)
  - VRAM: `0 MB` (DXGI 成功查询，当前处于空闲状态)
- **原始数据**：曲线数据双向持久化于 [`docs/evidence/memory_curve.csv`](evidence/memory_curve.csv) 与 [`build/evidence/memory_curve.csv`](../build/evidence/memory_curve.csv)。

### 4.4 GUI 事件到对应帧提交延迟 (VR4-05 / afterSynchronizing -> frameSwapped)
- **测量方式**：真实产品界面 `Main.qml`，50 次真实用户事件（抽屉折叠切换、搜索聚焦）并以 `afterSynchronizing` 挂载单次队列排队至 `QQuickWindow::frameSwapped` 信号实测，绑定业务序号同步，未呈现帧数 `unswappedCount == 0`。
- **渲染后端**：Direct3D 11
- **分位数测量结果**：
  - **p50**: `13.21 ms`
  - **p95**: `21.01 ms` (目标 ≤ 100ms)
- **验收结论**：**实测通过**。

### 4.5 独立高 DPI 进程缩放与视口保留 (VR4-04)
- **启动模式**：三个独立进程分别设置 `QT_SCALE_FACTOR=1.0`, `1.5`, `2.0`。
- **实测指标**：
  - 1.0x: 物理 960×540, DPR=1.0, 控件可达, handle/mask 零命中, 截图 [`docs/evidence/workbench_dpi_1.0.png`](evidence/workbench_dpi_1.0.png)
  - 1.5x: 物理 1440×810, DPR=1.5, 控件可达, handle/mask 零命中, 截图 [`docs/evidence/workbench_dpi_1.5.png`](evidence/workbench_dpi_1.5.png)
  - 2.0x: 物理 1920×1032, DPR=2.0, 控件可达, handle/mask 零命中, 截图 [`docs/evidence/workbench_dpi_2.0.png`](evidence/workbench_dpi_2.0.png)
- **交互验证**：折叠状态 Ctrl+F 使搜索框获得焦点；Tab 键聚焦可见元素；连续运行切抽屉项目不产生 dirty，四态与参数草稿完整保留；物理 grab 尺寸与逻辑尺寸严格匹配 `abs(physical - logical * DPR) <= 2`。
