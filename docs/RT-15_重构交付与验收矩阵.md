## 2. 宿主单源配置与交接规范 (RT-11, RT-13 / HS5-06)

为消除配置分叉与历史包袱，本仓库实施统一单源配置：
1. **依赖与路径单源**：[`tools/dependencies.yaml`](../tools/dependencies.yaml) 与 [`CMakeLists.txt`](../CMakeLists.txt) 定义 Qt、OpenCV、Python 的依赖发现与打包清单，修改一处即可作用于 CMake 配置与分发。
2. **构建与打包唯一入口**：[`tools/build.cmd`](../tools/build.cmd) 提供一键编译（`--build`）、全量测试（`--test`）及分发打包（`--package <dir>`）；[`tools/package_app.py`](../tools/package_app.py) 遵循直接构建与全新安装策略，内置安全目录守卫（禁止指向源码/根目录），并通过 `--test-verify` 进行负例自检。
3. **视觉主题单一真相源 (SSOT)**：通用控件全面回归 `quickui::quickui` 原生样式；业务四态状态色（灰、蓝、绿、红）与状态徽标在 [`src/ui/Theme.h`](../src/ui/Theme.h) 与 [`src/ui/qml/NodeDelegate.qml`](../src/ui/qml/NodeDelegate.qml) 统一定义，无外部冗余复述。
4. **动态插件加载单一真相源**：[`src/plugins/PluginLoader.h`](../src/plugins/PluginLoader.h) 与 [`src/sdk/include/visionrt/sdk/Module.h`](../src/sdk/include/visionrt/sdk/Module.h) 统一规范 C++ 插件动态加载与 `visiontoolsModuleApi` 导出接口，统一以 `module_index.yaml`（`variant`, `modules`, `tools`, `runtime_files` 映射模型）为唯一模块映射契约，杜绝重复键与 JSON/XML 多格式分叉。
5. **证据归档单一入口**：测试代码仅输出到构建临时目录（默认 `--evidence-dir build/evidence`），严禁自动测试改写源码 `docs/`；由独立脚本 [`tools/archive_evidence.py`](../tools/archive_evidence.py) 显式复制归档到文档引用目录。
6. **任务账本单一真相源**：仓库根目录仅保留一份 [`WORKLOG.md`](../WORKLOG.md)，杜绝第二份进度文件。

## 4. 核心性能与交互回归实测数据 (HS5-01 ~ HS5-06)

### 4.1 联合接口与安装 SDK (HS5-01 / VR5-01)
- **固定 module_index.yml 规范**：以 `schema_version: 1` 和 `modules` 列表（`registry_name`, `path`）为唯一规范，统一在 `SchemaYaml.h` 与 `SchemaYaml.cpp` 实现 `parseModuleIndexFile` 与 `parseModuleIndexYaml`；
- **SDK 验证器 CLI**：`visionrt_validate_tool --index <file>` 针对重复注册名、越界路径、非法结构等提供严格负例拦截；
- **原子批处理注册**：`PluginLoader::loadIndex` 采用局部暂存与失败回滚设计，若索引中任意一项校验或加载失败，不提交任何项，原有正常注册绝不被破坏；
- **独立 SDK 消费工程靶场**：`tests/sdk_consumer` 完全在屏蔽 VisionRT 源码和构建目录的独立目录下运行，仅依赖安装导出的 `VisionRT::ToolSDK`、OpenCV 与 yaml-cpp，不链接 Qt 或 InferRT。

### 4.2 真实 DLL 依赖与生命周期 (HS5-02 / VR5-02)
- **真实传递依赖夹具**：构造 `test_plugin_a` 依赖 `test_dep_a`（返回 `101`），`test_plugin_b` 依赖 `test_dep_b`（返回 `202`）；两个独立 `PluginLoader` 并发加载执行，各自计算结果恒等正确；
- **Win32 错误 126 子进程真实隔离**：子进程删除 `test_dep_a.dll` 保留主插件 `test_plugin_a.dll`，触发真正的操作系统 DLL 加载器错误代码 `126`（The specified module could not be found），断言错误消息包含真实 Win32 诊断；同时 `test_plugin_b` 成功加载运行不受影响；
- **预设进程 DLL 目录保留**：测试前调用 `SetDllDirectoryW` 设置非空目录，在插件并发加载、成功与失败后断言原预设目录未被擦除或篡改，并在测试结束前完全还原；
- **中文与空格路径**：将包含 `module_index.yml` 与依赖动态库的完整安装包放置于含有中文与空格的路径（如 `临时 测试 目录`），从索引解析到执行验证全部通过；
- **生命周期与卸载顺序**：持有输出快照期间释放实例与 loader，读取像素与数值无内存非法访问；断言 `pluginDestroy` 严格在动态库 `FreeLibrary` 之前发生。
