# 整体架构复核与进一步收敛

## 已有设计应保留

| 仓库 | 当前合理设计 | 后续措施 |
|---|---|---|
| Contracts | DataRef/Array 所有权句柄，类型契约，参数读写辅助，类/函数统一适配 IToolInstance | 保持可写数据、工具自身并发责任；收紧模板合法类型，不增加权限矩阵或 COW |
| VisionTools | 正式内核与工具包装分开；手工取参/封装；Python 作者 SDK 单一源；函数/类均已有路径 | 需要持状态用类，无状态用函数；复用现有 Input/OutputParameters，不再为界面生成算法类 |
| VisionRT | JSON 声明与工厂分离，基线按稳定端口名绑定，R45目标改PortId；异步读回/管理刷新；Theme 单例 | 新编辑器作为作者入口接入现有目录和刷新链，不成为第二套运行时 |
| 三仓测试 | 已改进 focused 入口、显式分组、真实 Owner 与工厂断言 | 完成遗留时序/skip/指标收尾，按实际职责拆巨型文件，不按行数机械拆文件 |

## 值得优化，但不作为本轮大重写

1. AppController 仍承担较多门面职责。已有 ProjectOperations/ResultPresentation 提取应继续使用；自定义编辑器草稿单独控制器，操作完成仍回现有管理链。不要把每个按钮拆成抽象服务。
2. ToolDefinition 同时表达运行契约与 UI 元数据对当前体量是可接受的。新增id/next字段后复用，不为编辑器新造一套 schema AST/ORM。定义、节点配置、运行输出三者身份要明确。
3. 类型信息必须由 Contracts TypeSpec 和现有解析器决定，界面中文显示复用 displayTypeName；不能给 UI 一个静态 enum 表后另写不同 token 转换。
4. 继续依靠 RAII 管理 C++ 实例、Array 完整句柄和 Python owner。当前 numpyView 修复的重点是完整 Storage 依赖保活，不是额外复制数据。不会通过给数据加 readonly 规避跨语言寿命问题。
5. 新组件名应体现用途：ToolPortListModel、CustomToolStore。避免 Manager/Helper/Common/Context 的泛化堆叠。测试命名以结果读回、参数规范、安装替换等具体职责为准。
6. 跨仓公共宏统一、无 Qt 核心拆分、通用热插拔平台继续延期；除非有明确新消费者或测量收益，不纳入本轮。

## 与用户既有交互要求的兼容清单

这些是新增功能必须保持的回归边界，不表示本次逐像素复验全部已通过：

- 普通参数行风格一致，上层输入按钮按模式高亮；没有多余占位解释、重建资源黄色说明或空候选提示行。
- 输出数据列只保留既有复制；新增工具编辑器里的 JSON 预览不等于恢复运行输出的“查看诊断 JSON”菜单。
- 工具和底部毫秒显示三位小数，不用 `<0.001`；单节点运行不累计底部全流程时间。
- Loop 只发布轻量状态，停止后读回重资源；编辑器保存不增加逐轮图像/ROI 渲染。
- 图像仍支持项目已有灰度/BGR/BGRA 显示路径；Image 是唯一图像数据类型。
- EasyTouch/Assist 沿用现有开关及排空机制，工具定义编辑不会永久开启预览。
- 状态消息由工具输出，业务规则不由宿主补充；图像算法使用 OpenCV/其他开源实现，不引入 HALCON。
- 日志沿用 spdlog 与当前 UI 桥接；新编辑行为只记录有意义的提交结果，避免高频输入/拖动刷日志。

## 本轮完成的定义

完成 T45-01～18、实际候选安装验收及证据绑定后，才把“设计已完成”升级为“功能已交付”。本报告和 HTML 原型是设计交付，不是已合入三仓的实现或生产发布。

## 不为数字编号增加的东西

不添加UUID/order双份顺序，不按最大id扩容，不新增每端口一个派生UI类，不建全局端口历史数据库，不保持长期双键兼容，不用生成器接管作者算法代码。数字ID与值合法性由一处规范；数据载体没有只读/读写属性。Contracts参数基类服务作者，PortDefinition服务宿主声明，二者不混成通用脚本对象框架。
