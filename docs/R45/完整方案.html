R45 完整整合方案：三仓验收整改 + 自定义工具 + 数字参数编号

日期：2026-11-03（Asia/Shanghai）。本包整合 R44 全部验收问题、改进方案与最新已确定的数字编号方案；设计正文、Specs、Tickets、伪代码、示例和原型已统一，旧字符串访问方案不再作为并行目标。

已确定的接口

  • 端口以稳定数字 id 为身份；Python 使用 inputs[1]、outputs[2]，C++ 参数 Reader/Writer 接受 PortId。
  • 端口数组排列只控制 UI 显示顺序。拖动不重编号，新增分配新 ID，已提交删除的 ID 不复用。
  • 输入 0 为“上层工具状态”；输出 0/1 为“状态码/状态信息”。固定声明由公共规范化入口注入，不写进工具 JSON；仍在普通参数接口中，由工具解析和包装值。
  • Fixed 工具输入业务编号从 1 起；逻辑模型同样保留输入 0，但不因此新增上层状态。输出业务从 2 起；init 独立从 0 起，无固定端口。
  • 工具顶层 name_en 继续标识注册工厂；端口 name_en 改为可选说明，不用于取参、绑定、排序或兜底查找。
  • 当前载荷、34 种具体类型、所有权、零拷贝、合法性规范、主题、Loop 渲染及已有交互要求继续保留。

版本与事实边界

自定义工具界面与行为

入口与整体布局

“工具 → 自定义工具…”打开工作台内可调整大小的 Dialog，复用现有窗口、Theme、标准参数行和图标资源。左侧为工具列表，支持搜索、新建、复制、删除；中间为当前工具信息与“输入参数 / 输出参数 / 初始化参数 / 代码”页；右侧为选中参数的属性（用 stage + id 保持选中）；底部为当前工具的“撤销修改 / 应用 / 关闭”。只保留一个编辑器实例。未应用修改仅存在草稿中，运行仍使用已发布定义。

工具列表展示名称和实现类别；Python 类与函数明确区分。有状态读图等继续使用类，纯处理优先函数。新建 Python 工具要求名称、稳定工具标识、实现类别；应用前可修改新标识，第一次提交后锁定。工具名称、分类可改。原型采用项目当前浅色主题，而非另建视觉语言。原型代码页为草稿演示；生产首期显示入口文件并提供“打开代码文件”，代码在外部编辑器保存后由同一刷新入口加载，不把算法编辑器扩成 IDE。

“导入工具包…”复用当前包验证和依赖安装流程，支持已注册 C++ 函数/类以及 Python 工具；不是让用户在声明编辑器编译 C++。已安装内建/Host/Assist 工具可查看，定义不可直接覆盖。用户自有 Python 工具可编辑，复制时同时复制其代码与声明列出的资源、配置新 ID/目录；只改 ID 的空壳复制不能算成功。C++ 工具的函数/类由注册工厂决定，JSON 继续 kind: cpp；界面不提供伪造新工厂的复制入口。

参数列表

列表列为拖动柄、参数编号、名称、类型；不再放重复的“显示序号/英文标识”两列。输入第一行为“上层工具状态”；输出前两行为“状态码”“状态信息”。固定行显示锁定标记，可选中查看，删除、拖动、改名、改类型、改默认值按钮禁用；后端同样拒绝绕过 QML 的修改。固定行不进入 JSON。初始化页没有这些固定行。

业务行通过“添加参数”创建并自动分配新编号；名称、类型、默认值可编辑，编号只显示不可手工改写。可选英文别名放在属性区，不是必填项。上移、下移和拖动移动的是整个 PortDefinition，关联、约束和默认值一起移动。不能移动到固定前缀内，也不能跨输入/输出/初始化页拖动。编号按方向固定：inputs 0、outputs 0/1 为系统保留；业务输入从 1、业务输出从 2、init 从 0 分配。界面显示实际 id，不用 rowIndex+1 冒充编号。按参数页过滤时，仍以同一声明数组的相对顺序为准；变更页面用 ui.tab，不引入第二个排序表。

同一方向内 id 唯一，init/inputs/outputs 各有独立编号空间，允许不同方向同号。显示名和可选 name_en 改名不影响任何绑定；名称不是身份，不再按名称拒绝两个独立端口。编号提交后不可改，不复用已提交删除编号；需要新的参数就分配新 id。复制整个工具保留参数 id 和各 next_port_id，另分配工具顶层 name_en，因此复制后的代码仍可直接使用原编号。拖动只移动整条定义，不改编号、默认值、关系或取参代码。

参数属性

基本属性：名称、参数编号（只显示）、类型；输入/初始化显示默认值。类型是整数、浮点数、布尔、字符串、图像、ROI、数组；数组进一步选择元素类型与一至四维。名称显示中文；新建工具顶层 name_en 仍按现有标识规则校验，端口 id 按无符号整数及保留号规则校验。

“更多属性”仅按现有声明能力展开：标量数值 min/max/step/decimals、合法 options、参数页/group、文本/文件/目录/path 编辑器、ROI/数组编辑器、图像关联、alignment、same_geometry_as、颜色次序。候选项来自后端和当前草稿的真实端口，禁止手填悬空引用。输出页只暴露现有输出允许的类型/关系/显示属性，不出现输出默认值、数值范围或输入编辑器。type_from 是 Host 工具特性，不是自定义 Python 类型选项。

Int64 和数组/ROI 原始值作为 QString 文本提交给 C++ ValueJson 解析；不要经过 QML Number 再 stringify。图像没有像素默认值编辑框；运行时图像照旧由上层输入、手工入口或工具生成。ROI 编辑器沿用已有定义，不再独立发明 ROI 编码。

类型修改时先在草稿计算默认值、关系和范围是否仍合法。能保留就保留，不能保留时在当前属性区清晰列出将清除的具体字段，确认后变更，不在每个参数框里写“不可用/null/始终执行”之类占位说明。输入框字体、字号、颜色、行高统一绑定 Theme；设计器的必要保存错误放底部或错误对话框，普通运行参数框不额外变红。

固定参数与运行值的边界

“不可修改”只指工具定义。节点运行时输入 0（上层工具状态）仍为普通 Int 输入，默认 0，用户可以手输或切换上层输入；切到上层模式按钮即高亮，和是否已绑定无关。宿主规范类型/范围，传给工具；不能因其非零提前跳过普通工具。工具自行决定继续、降级或返回失败。

输出状态同样包含在 outputs 参数集合中，由 C++ toolResult/OutputParametersBase 或 Python result/pack 填入。宿主验证结果契约，不能替工具覆盖成功码或错误文字。编辑器锁定的元数据不意味着载荷只读，不新增 writable/readonly 属性。

首期创建工具固定为 node_model: fixed（可省略默认）；既有 expression/condition/select 保留各自节点配置编辑器。不会把所有工具升级成带执行条件的动态节点模型。

应用、删除与工程影响

应用只提交当前工具。取消/关闭可丢弃当前草稿；多个工具草稿不偷偷合并成跨文件事务。仅调整顺序/中文名时，现有工程绑定、值及代码取参 id 不变，不重建 Python 入口代码。改变类型、删端口、收窄范围时，用现有项目对账规则在副本上产生精确影响：哪些绑定将清除、哪些字面值将规范、哪些节点成为不可解析；有实际影响才集中确认一次。

删除工具显示当前工程的引用节点和数量，确认后删除自有声明，保留引用节点为“工具缺失”以便用户修复；不连带删工程节点。未打开的工程不全盘扫描，不承诺自动迁移。工程改动标 dirty，不静默覆盖工程文件。删除最后一个用户工具合法，列表为空仍可新建。

运行期间允许编辑草稿；应用/删除/安装/切换目录等待既有运行与管理操作空闲。不能在 Loop 每轮重载，不因编辑器打开而停用正常图像显示。应用触发的实例释放、读者排空、Assist 结束、Python refresh 复用现有管理链，GUI 不持锁同步等待。

JSON、PortId 与全部参数类型

这是目标协议规范，基线 schema5 不接受这些新增字段；实施后使用 schema6。没有把设计示例假称当前版本可直接加载。

一、参数身份与显示顺序

PortId 为 uint32，取值 0～4294967295。身份由“工具/节点 + 参数方向 + id”共同确定；同一方向不能重复。参数数组位置只控制显示，排序不得改 id。Python inputs[1] 按字典键 1 读取，不是读数组第二项。C++ 按数字 ID 查询，同样不按 UI 行号。

新建工具示例：

{
  "schema_version": 6,
  "name_en": "custom.image.threshold",
  "name_zh": "图像阈值处理",
  "version": "1.0.0",
  "implementation": {
    "kind": "python_function",
    "package": "custom/image/threshold",
    "file": "tool.py",
    "symbol": "execute"
  },
  "ui": {"category": ["自定义", "图像处理"]},
  "next_port_id": {"init": 0, "inputs": 4, "outputs": 3},
  "ports": {
    "inputs": [
      {"id": 1, "name_zh": "阈值", "type": "int", "default": 128,
       "constraints": {"min": 0, "max": 255}},
      {"id": 2, "name_zh": "输入图像", "type": "image"},
      {"id": 3, "name_zh": "检测区域", "type": "roi", "default": [],
       "relations": {"image": {"stage": "inputs", "id": 2}}}
    ],
    "outputs": [{"id": 2, "name_zh": "输出图像", "type": "image"}]
  }
}

这里 inputs[1] 永远是阈值，inputs[2] 是图像。把图像行移到阈值前，JSON 数组改为 id=2、1、3，工具与工程仍按原 id 访问。不添加 order、UUID 或名称到编号的运行期回退表。

二、固定编号与分配

方向 系统编号 业务起点 分配规则
init 无 0 独立空间；函数工具不声明 init
inputs 0：上层工具状态，仅 Fixed 注入 1 所有模型保留 0；逻辑工具不因升级多出上层状态
outputs 0：状态码；1：状态信息 2 所有工具通过普通 outputs 返回这两项

公共字段不在 JSON 中声明。固定行的中文名、类型、编号、位置不可在编辑器修改；其运行值由工具正常处理。“上层工具状态”默认 0，宿主按契约传入，非零不触发普通工具的框架跳过。

每方向一个 next_port_id 高水位，值是下一次分配编号，不是当前参数数量。必填三个方向值；空函数工具通常为 init=0、inputs=1、outputs=2。它必须大于该方向所有业务 id，且不小于业务起点。允许保留空洞，删除不回退计数；复制整工具保留计数。4294967296 是耗尽哨兵，只能出现在 next_port_id，不能成为 port id；用 uint64 存计数，分配时先检查再加一。无需同时保存 retiredIds/tombstone 列表。

为了避免把新参数接到旧工程引用，新加参数使用高水位，已经发布的 id 不重新分配给另一个含义。关闭未提交草稿可以整体撤销草稿编号分配；提交后不能回收。外部编辑声明也必须遵守此作者契约，宿主仅凭删除后的 JSON 无法证明某个历史编号从未被复用；不为此建立历史数据库或哈希链。

id 是整数，拒绝字符串 "1"、布尔、负数、超范围或非整数。Python 键用 type(key) is int 检查，不能把 True 当 1。SDK应在写入dict之前拒绝bool键；宿主对作者直接返回的裸dict只能检查现存键，无法恢复Python构造字典时已经合并覆盖的历史键。名字可改，编号不可通过普通属性编辑器改写。

三、名称与参数定义

PortDefinition 仍是宿主的一条参数元数据：新增 id，保留 nameZh/type/default/constraints/ui/relations。端口 name_en 可省略，填写时只用于作者阅读和迁移说明；不参与身份、绑定、取值或别名兜底，也不要求依赖它保持唯一。

工具顶层 name_en 仍是全局唯一工具 ID，与 native 工厂、module_index、Python 装配关联，继续必填，不能因为端口编号化就删掉。代码中的枚举/常量由工具作者手写，不启用构建时代码生成器。

四、关系与交互映射

所有端口关系统一结构为 {"stage":"inputs|outputs|init","id":整数}，使用现有 PortRef 概念，禁止一部分仍写 inputs.images 或另一部分写 inputs.2。包含 image、alignment、same_geometry_as、path_mode，以及 Host 的 type_from.flow/node/port。类型合法性规则继续使用现有验证器；只替换引用的身份部分。

智能点选（目标格式片段）：

"interaction": {
  "helper": "visiontools.assist.circle",
  "inputs": [
    {"helper_port_id": 1, "source": {"stage": "inputs", "id": 2}}
  ],
  "proposals": [
    {"helper_port_id": 2, "target": {"stage": "inputs", "id": 3}}
  ],
  "roi_kinds": ["circle"]
}

以上 helper 名称和编号仅为结构示例，落地必须取实际 helper 声明映射；不是对当前端口号的事实断言。输入映射左侧查 helper.inputs，proposal 左侧查 helper.outputs；右侧查当前工具的 PortRef。不要把数字键塞进 JSON 对象后再靠字符串转数字恢复。helper 公共状态输入/输出同样按公共编号处理。

动态表达式的 AST 变量继续使用 symbol，例如 mean(values)；symbol 不等于端口 id。表达式配置保存 port_id=数字，运行时按变量配置把 inputs[id] 放进符号环境。修改显示名、显示顺序不改 symbol；显式改 symbol 才涉及公式校验。不将公式全文替换成数字，也不恢复 name_en 作为取参键。

五、完整具体类型

token 显示 C++ Python 声明默认
int 整数 std::int64_t int 0
float 浮点数 double float 0.0
bool 布尔 bool bool false
string 字符串 std::string str ""
image 图像 DataRef<Image>；Image 载荷 vector<cv::Mat> list[numpy.ndarray] 不存像素默认值
roi ROI DataRef<ROI>；载荷 vector<vector<vector<double>>> list[list[list[float]]] []

数组元素 token 为 uint8/int32/int/float32/float/bool/string，在前面加 1～4 个 vec_。例如二维 float32 是 vec_vec_float32，四维字符串是 vec_vec_vec_vec_string。全量 34 项见 类型矩阵.csv；不是仅做界面选项，全部须经生产 TypeSpec/ValueJson 和真实工具边界验证。

ABI8 当前 Array 是带存储/形状/Owner 的运行时载体，作者辅助允许嵌套 vector；不能在新文档中把所有运行值写成裸 vector。Python Dense 数值数组可能是 ndarray，ragged 和字符串是嵌套 list。图像始终是一个 Image 类型（C++ vector<cv::Mat> / Python list[ndarray]），不另起“图像批次”类型。ROI 使用既有三层 double/float 结构和类型码，含义与 Contracts/ROI 一致。

**与早期约定的差异：**此前要求 Python 数组统一为嵌套 list，当前 ABI8 已采用 Dense 数值 ndarray / ragged 与字符串 list。本方案建议沿用当前 ABI8 并明确作者观察类型，不把它写成已字面满足早期纯 list 约定。确需纯 list 的算法可以在工具边界显式转换并承担分配成本；不要在所有宿主端口无条件复制。

Missing/null 表示没有值，不是新的可选类型。标量没有 uint8/int32/float32 独立端口类型，它们只在数组元素选择中出现。路径是 string + ui.editor，不另加 Path 类型；矩形是 ROI 编辑器，不另加 Rect 数据类型。

本轮 ABI9 只改变参数身份/接口键，不改变 ABI8 已有 Array 的载荷布局和作者观察类型。上述纯 list 与 Dense ndarray 的历史差异仍明确保留，不偷偷改变图像/ROI 的表达。

六、默认值与约束

输入和 init 默认值、标量 min/max、合法 options、ui.step/decimals/参数页、图像关系继续复用当前能力。输出不写 default/constraints/ui。图像不保存像素默认值；Missing 是值状态，不是新类型。Int64 和嵌套数组默认值通过 QString 原始 JSON 文本传给 ValueJson，禁止先转 QML double。PortId 自身 32 位可被 JavaScript Number 精确表示，这不能推出 Int64 载荷也可以如此处理。

只做契约合法性/范围规范，不增加业务状态拦截；错误消息仍由工具决定。fixed 是 UI 定义角色，不是数据权限；不增加 readonly/writable/COW 标记。

七、工程与输出文本的 JSON

工程 format7 的输入绑定、初始化值、类型签名按带 port_id 的条目数组序列化。数组顺序不作为身份。图像/Array/ROI 值编码沿用 ValueJson Stored，不把实际像素直接塞进端口定义。

{
  "format_version": 7,
  "node_fragment": {
    "tool_id": "custom.image.threshold",
    "inputs": [
      {"port_id": 0, "mode": "literal", "value": 0},
      {"port_id": 1, "mode": "literal", "value": 128},
      {"port_id": 2, "mode": "upstream",
       "source": {"flow_id": "flow_1", "node_id": 10, "port_id": 2}}
    ]
  }
}

这是字段结构片段，node_fragment 是说明容器，不是完整工程文件。执行条件 source、跨流程 Receiver/Select、输出类型来源、节点复制重映射和所有结果上下文也全部使用数值 port_id。复制节点只重映射 node/flow 身份，不能给同一工具的端口重新编号。

Python 执行信封为 {"outputs": {0: code, 1: message, 2: image}, "detail": ""}，这是 Python 对象而不是 JSON 字符串。输出文本整体导出用 {"outputs":[{"port_id":0,"value":0},…],"detail":""}；单个端口的“复制”仍只导出该参数值，按现有 ValueJson 规则，不能借此恢复诊断菜单。

保存的事务边界

元数据修改只写一个声明文件，使用 QSaveFile(QString) 并禁用直接写回退；write 完整成功后 commit。写前保存原始字节与文件摘要，在应用时发现外部改动则要求重新载入/明确覆盖；一个轻量内容比较即可，不建立数据库版本系统。应用单个当前工具；失败时保留草稿。

创建新工具：先在扫描根外准备代码/资源/声明；校验路径、声明和所需文件，再把代码目录发布到最终位置，最后以原子写发布 JSON。JSON 是发现入口，写出它之前扫描器不能看到半成品。失败清理本次新建目录，绝不能删已有用户目录。无声明的孤立代码目录不能被自动当工具加载。

已有代码首期由外部编辑器保存，“刷新工具”通过既有 Python 重新加载链生效；参数移动/改名不重新生成或重写代码。新建 Python 模板仅创建一次，不能每次构建跑生成器。不要宣称 QSaveFile 能原子更新 JSON 与多个代码文件；本轮不实现跨文件事务平台。后续若支持内嵌编辑，代码保存与声明提交分开命名并保留备份。

删除时先撤销/移走声明使其不可被发现，协调器释放实例后处理自有代码目录；若目录仍被其他自定义声明引用则保留。不强制释放其他消费者持有的图像/Array owner。逻辑删除与实际磁盘清理失败分别记录，不能删到一半却继续显示“删除成功”。无需实现全盘垃圾收集。

应用重载顺序

  1. 草稿经现有 parser/normalizer/validator；检查路径和工厂存在性属于合法性，不执行算法试跑。
  2. 在工程副本上使用现有 reconcile 规则算差异，需确认时只确认具体破坏性变更。草稿打开版本与当前文件不一致时重新预览。
  3. 通过既有管理入口禁止并发 Apply/Run/Reset/Close 重叠；有运行时等其结束，不在 GUI 同步 stop-and-wait。
  4. beginDrain 排空显示、文本和 Assist；协调器释放将替换实例。现有 Owner/模块保活继续生效，不另立只读或复制策略。
  5. 提交单文件声明，扫描候选合并目录，调用既有 requestRefresh/refreshFinished 更新工厂。只有成功完成才替换可见目录、应用工程对账并清脏状态。
  6. 普通写入/装配失败：恢复旧声明字节，重新加载旧目录；显示失败，草稿仍在。若旧目录恢复也失败，保持运行禁用并提供具体错误/重试，不能把半失败说成“旧实例仍正常”。

该协议保证普通失败的可恢复性，不声称断电时多目录全事务。元数据单文件替换是原子的；新建 JSON-last 保证不发现未完成条目。管理状态尽量复用 ProjectOperations/已有 refresh 命令，避免另建平行状态机。

工程兼容与资源寿命

纯排序/显示名变更应无损。类型变更/删端口按 ProjectStorage 既有规则处理 current project，提示准确内容后生效，项目 dirty 不静默保存。项目中的缺失工具节点保留，便于用户恢复声明。旧结果与正在读取的 Image/ROI/Array 清理仍遵守现有读回 ACK 与跨语言 owner 生命周期；若外部持有 view，它延长资源寿命，不强制卸载底层模块。

自定义工具保存不会重置底部“已运行”时钟；未实际运行则不写运行指标。双击单工具运行不累计底部流程时间等原有规则保持；工具代码返回错误文字不额外拼节点前缀。日志只记录一次保存/删除/重载结果和必要错误，不对每个拖动像素、每个列表行刷日志。

Contracts 与工具参数接口

目标 C++ 以 using PortId = std::uint32_t; using Values = std::map<PortId, PortValue>; 替换字符串 map。复用现有容器、参数基类和注册机制，不为按编号取值新建通用参数框架。保留稀疏编号，因此内存随实际端口数增长；不能用最大编号扩一个巨大 vector。元数据 vector 用于显示顺序，Values map 用于执行取值，这两个职责不同。

C++ 推荐 InputReader::integer(id)/image(id)/array(id) 等返回已有 ReadResult，OutputWriter 接受 PortId；合法读写路径不拷贝像素。const Values 使用 find/at，避免 operator[] 插入空值；不为追求一模一样的 [] 语法再套一层容器。Python dict 使用 int 键，按 inputs[1] 和 outputs[2] 访问。数字写错仍可能错误，工具可用手写 enum/constexpr/IntEnum，测试以业务结果识别；数字编号消除英文拼写依赖，不宣称消除所有取参错误。

ToolResult 保持 outputs/detail 信封，输出 0/1 由工具侧 toolResult()/pack()/result() 写入。InputParametersBase 解析固定输入 0，具体子类解析业务编号；OutputParametersBase 负责统一包装，不让宿主补状态。SDK writer 不把字符串强转 Bool/Float 掩盖作者错误。initialize/release 的 ToolStatus 字段 code/message/detail 不属于端口 map，生命周期返回结构不用改成数字键。

PortIssue.field 当前还被路径错误等非端口上下文使用，不能全仓机械改成整数。可保持 field 作为显示上下文字符串，端口 helper 用编号生成文字；如确需机器可读端口位置，加 optional<PortId>，无端口的路径错误保持空。以实际使用选择最小变更，不建立泛化诊断树。

不只是 UI 排序改动

生成一次迁移映射

为每个工具建立一份可审阅映射，公共端口按固定规则转换。没有作者指定编号时，可按迁移前原始业务数组顺序分配输入1起/输出2起/init0起；映射一经批准，新代码与新工程必须都消费同一份结果。此转换工具是迁移辅助，不是每次构建或运行的生成器。

若作者希望阈值为1、图像为2，而旧声明图像在前，则明确写映射 images→2、threshold→1，不能先自动编号后再人工只改声明。当前示例以新工具目标编号为准，不推断任何已安装工具的真实编号。

动态节点的端口来自旧节点配置，要为每个节点生成本地映射。表达式 variables 与 program 各自对应输入/输出，保持符号表；既有宿主静态参数占号后，动态编号从剩余高水位继续。复制节点保留其端口id，只重映射node/flow引用。

已缺失声明的工程无法从字符串可靠还原端口号。保持原文件，列出缺失工具及引用；等补齐旧声明/映射再转换。不要据当前排序猜号、丢端口后继续显示“转换成功”。迁移输出应附简短摘要：工具数、节点数、成功/未转换项、原文件位置；无需全量哈希链或历史数据库。
