## 2. C++ 工具参数子类

```cpp
namespace In { constexpr PortId Threshold = 1, Images = 2; }
namespace Out { constexpr PortId Images = 2; }

struct ThresholdInputs : InputParametersBase {
    std::int64_t threshold;
    DataRef<Image> images;
    // 以下回调签名需与现有 Parameters.h 对齐，不新增第二套基类。
    ToolStatus readFields(InputReader& reader) override {
        auto t = reader.integer(In::Threshold);
        if (!t) return {kContractViolationStatus, "阈值输入不合法", t.issue().describe()};
        auto im = reader.image(In::Images);
        if (!im) return {kContractViolationStatus, "图像输入不合法", im.issue().describe()};
        threshold = t.value(); images = im.value();
        return {};
    }
};

ToolResult execute(const Values& values, const ToolServices&) {
    ThresholdInputs in;
    auto parsed = in.parse(values); // Fixed 基类解析输入 0，子类解析业务编号
    if (!parsed) return toolResult({{Out::Images, Missing{}}}, parsed);
    if (in.upstreamStatus != 0) // 本工具的业务选择，宿主不提前阻断
        return toolResult({{Out::Images, Missing{}}}, {in.upstreamStatus, "上层工具未正常完成"});
    auto image = thresholdAlgorithm(in.images, in.threshold);
    return toolResult({{Out::Images, std::move(image)}}, {0, ""});
}
// 工具工厂仍 registerFunction<&execute>(registry, "custom.image.threshold")。
```

readFields/parse 返回已有 ToolStatus；参数读取失败如何形成业务消息由工具确定。const Values 的底层读取用 find/at；写输出用 outputs[id] 或既有 OutputWriter，错误键不能因为 [] 被自动插入成“默认成功”。

## 3. Python 工具与状态封装

```python
UPSTREAM_STATUS = 0
STATUS_CODE, STATUS_MESSAGE = 0, 1
THRESHOLD, IMAGES = 1, 2
OUT_IMAGES = 2

def result(business_outputs, code=0, message="", detail=""):
    # 作者SDK实际实现还要沿用现有重复/保留键错误接口。
    outputs = dict(business_outputs)   # 浅拷贝小字典，不复制图像/数组载荷
    outputs[STATUS_CODE] = code
    outputs[STATUS_MESSAGE] = message
    return {"outputs": outputs, "detail": detail}

def execute(inputs):
    if inputs[UPSTREAM_STATUS] != 0:
        return result({OUT_IMAGES: None}, inputs[UPSTREAM_STATUS], "上层工具未正常完成")
    return result({OUT_IMAGES: algorithm(inputs[IMAGES], inputs[THRESHOLD])})
```

参数子类继续提供 parse/read_fields/write_fields；只把键改为数字。逻辑工具没有注入 input0，其参数类不能无条件读取这个键。生命周期 initialize/release 仍返回 code/message/detail 字段，不是上面的执行信封。

桥接遍历声明端口，逐项以整数构造 py::dict 的键；返回时严格校验 int 键，不能调用 str(key) / int("1") / int(True) 修饰坏输出。Image/Array 转换函数及 owner capsule 沿用。

## 6. 应用与异步生命周期

```text
Apply当前工具
  → 用正式解析器构造候选（schema6）
  → 在当前工程副本执行同一 reconcile 得出影响
  → 必要时一次确认；版本/文件已变化则重算
  → 既有管理入口：运行中/closing/另一管理操作时不提交
  → beginDrain：显示、文本、Assist 收尾
  → 协调器释放将替换的实例
  → 原子提交声明，合并扫描候选工具目录
  → requestRefresh / refreshFinished
      成功：一次发布定义与工程对账，标dirty，清当前草稿脏状态
      失败：恢复旧声明并加载旧目录；恢复失败明确保持运行不可用
```

先后关系沿用当前管理对象，不按此伪代码新造另一套 coordinator。GUI 不持控制锁同步等待。外部保活的图像/Array 仍延长底层 owner/模块，不强制释放。

## 8. 有效读回测试

```text
小图真实worker进入测试gate → 发invalidate → GUI排队回调可执行
→ gate未释放前不提前ACK/完成/发布旧图 → 放行worker
→ 等待恰好一次readersIdle → 再请求新图成功
```

固定时长仅是失败超时上限，不以“机器必须慢到收到三个心跳”为成功标准。测试 hook 仅测试构建启用，发布路径不增加逐图开销。
