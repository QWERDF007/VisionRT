# 自定义工具界面与行为

## 入口与整体布局

“工具 → 自定义工具…”打开工作台内可调整大小的 Dialog，复用现有窗口、Theme、标准参数行和图标资源。左侧为工具列表，支持搜索、新建、复制、删除；中间为当前工具信息与“输入参数 / 输出参数 / 初始化参数 / 代码”页；右侧为选中参数的属性（用 stage + id 保持选中）；底部为当前工具的“撤销修改 / 应用 / 关闭”。只保留一个编辑器实例。未应用修改仅存在草稿中，运行仍使用已发布定义。

工具列表展示名称和实现类别；Python 类与函数明确区分。有状态读图等继续使用类，纯处理优先函数。新建 Python 工具要求名称、稳定工具标识、实现类别；应用前可修改新标识，第一次提交后锁定。工具名称、分类可改。原型采用项目当前浅色主题，而非另建视觉语言。原型代码页为草稿演示；生产首期显示入口文件并提供“打开代码文件”，代码在外部编辑器保存后由同一刷新入口加载，不把算法编辑器扩成 IDE。

“导入工具包…”复用当前包验证和依赖安装流程，支持已注册 C++ 函数/类以及 Python 工具；不是让用户在声明编辑器编译 C++。已安装内建/Host/Assist 工具可查看，定义不可直接覆盖。用户自有 Python 工具可编辑，复制时同时复制其代码与声明列出的资源、配置新 ID/目录；只改 ID 的空壳复制不能算成功。C++ 工具的函数/类由注册工厂决定，JSON 继续 `kind: cpp`；界面不提供伪造新工厂的复制入口。

## 参数列表

列表列为拖动柄、参数编号、名称、类型；不再放重复的“显示序号/英文标识”两列。输入第一行为“上层工具状态”；输出前两行为“状态码”“状态信息”。固定行显示锁定标记，可选中查看，删除、拖动、改名、改类型、改默认值按钮禁用；后端同样拒绝绕过 QML 的修改。固定行不进入 JSON。初始化页没有这些固定行。

业务行通过“添加参数”创建并自动分配新编号；名称、类型、默认值可编辑，编号只显示不可手工改写。可选英文别名放在属性区，不是必填项。上移、下移和拖动移动的是整个 PortDefinition，关联、约束和默认值一起移动。不能移动到固定前缀内，也不能跨输入/输出/初始化页拖动。编号按方向固定：inputs 0、outputs 0/1 为系统保留；业务输入从 1、业务输出从 2、init 从 0 分配。界面显示实际 id，不用 rowIndex+1 冒充编号。按参数页过滤时，仍以同一声明数组的相对顺序为准；变更页面用 `ui.tab`，不引入第二个排序表。

同一方向内 id 唯一，init/inputs/outputs 各有独立编号空间，允许不同方向同号。显示名和可选 name_en 改名不影响任何绑定；名称不是身份，不再按名称拒绝两个独立端口。编号提交后不可改，不复用已提交删除编号；需要新的参数就分配新 id。复制整个工具保留参数 id 和各 next_port_id，另分配工具顶层 name_en，因此复制后的代码仍可直接使用原编号。拖动只移动整条定义，不改编号、默认值、关系或取参代码。

## 参数属性

基本属性：名称、参数编号（只显示）、类型；输入/初始化显示默认值。类型是整数、浮点数、布尔、字符串、图像、ROI、数组；数组进一步选择元素类型与一至四维。名称显示中文；新建工具顶层 name_en 仍按现有标识规则校验，端口 id 按无符号整数及保留号规则校验。

“更多属性”仅按现有声明能力展开：标量数值 min/max/step/decimals、合法 options、参数页/group、文本/文件/目录/path 编辑器、ROI/数组编辑器、图像关联、alignment、same_geometry_as、颜色次序。候选项来自后端和当前草稿的真实端口，禁止手填悬空引用。输出页只暴露现有输出允许的类型/关系/显示属性，不出现输出默认值、数值范围或输入编辑器。`type_from` 是 Host 工具特性，不是自定义 Python 类型选项。

Int64 和数组/ROI 原始值作为 QString 文本提交给 C++ ValueJson 解析；不要经过 QML Number 再 stringify。图像没有像素默认值编辑框；运行时图像照旧由上层输入、手工入口或工具生成。ROI 编辑器沿用已有定义，不再独立发明 ROI 编码。

类型修改时先在草稿计算默认值、关系和范围是否仍合法。能保留就保留，不能保留时在当前属性区清晰列出将清除的具体字段，确认后变更，不在每个参数框里写“不可用/null/始终执行”之类占位说明。输入框字体、字号、颜色、行高统一绑定 Theme；设计器的必要保存错误放底部或错误对话框，普通运行参数框不额外变红。

## 固定参数与运行值的边界

“不可修改”只指工具定义。节点运行时输入 `0`（上层工具状态）仍为普通 Int 输入，默认 0，用户可以手输或切换上层输入；切到上层模式按钮即高亮，和是否已绑定无关。宿主规范类型/范围，传给工具；不能因其非零提前跳过普通工具。工具自行决定继续、降级或返回失败。

输出状态同样包含在 outputs 参数集合中，由 C++ toolResult/OutputParametersBase 或 Python result/pack 填入。宿主验证结果契约，不能替工具覆盖成功码或错误文字。编辑器锁定的元数据不意味着载荷只读，不新增 writable/readonly 属性。

首期创建工具固定为 `node_model: fixed`（可省略默认）；既有 expression/condition/select 保留各自节点配置编辑器。不会把所有工具升级成带执行条件的动态节点模型。

## 应用、删除与工程影响

应用只提交当前工具。取消/关闭可丢弃当前草稿；多个工具草稿不偷偷合并成跨文件事务。仅调整顺序/中文名时，现有工程绑定、值及代码取参 id 不变，不重建 Python 入口代码。改变类型、删端口、收窄范围时，用现有项目对账规则在副本上产生精确影响：哪些绑定将清除、哪些字面值将规范、哪些节点成为不可解析；有实际影响才集中确认一次。

删除工具显示当前工程的引用节点和数量，确认后删除自有声明，保留引用节点为“工具缺失”以便用户修复；不连带删工程节点。未打开的工程不全盘扫描，不承诺自动迁移。工程改动标 dirty，不静默覆盖工程文件。删除最后一个用户工具合法，列表为空仍可新建。

运行期间允许编辑草稿；应用/删除/安装/切换目录等待既有运行与管理操作空闲。不能在 Loop 每轮重载，不因编辑器打开而停用正常图像显示。应用触发的实例释放、读者排空、Assist 结束、Python refresh 复用现有管理链，GUI 不持锁同步等待。

## 首期能力与后续范围

本轮交付：Python 函数/类新建编辑删除复制、所有具体类型、参数排序、固定行、schema 6 保存、持久目录、项目影响预览、安全刷新、现有 C++ 包导入可达。后续有实际需求再做 C++ 工程向导、内嵌代码编辑和多工具批处理。编辑已编译 C++ 的端口契约需要作者同步代码并重新打包，不把这一限制隐藏成 UI 自动完成。

## 原型行为范围

新版原型直接显示编号 0、1、2 等；可观察删除编号后新增不会填回旧号，拖动后编号保留；JSON 预览写出 id 和 next_port_id，省略固定端口。代码示例使用数字访问。它不是安装态产品，也不执行 Python/C++ 算法；原生包导入、高级关系编辑、文件系统失败恢复和 Qt 类型合法性仍按 Specs 实现，不由浏览器演示冒充验收。
