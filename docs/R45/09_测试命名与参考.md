## 新功能测试采用最小有意义集合

| 层级 | 重点 | 不做 |
|---|---|---|
| core/backend | schema6 数字编号/顺序/next 往返、固定端口不入 JSON、34 类型 token、Int64 精确值、重复标识/悬空关系、保存失败原文件不变 | 每种类型重复打开 34 次工作台 |
| bridge/model | moveRows/固定行后端拒绝、选择 stage+id 稳定、工程 diff 准确、只应用当前草稿 | 镜像复制实现细节的“自己测自己”断言 |
| QML 用户流程 | 新建→参数→排序→保存→再次打开，固定行操作禁用、统一主题绑定，删除空列表 | 极长工具名造景、全 DPI×缩放截图矩阵 |
| lifecycle | 读者/文本/Assist 在途时应用、close 冲突、失败恢复、外部 view 延寿 | 靠大图必须慢/固定 sleep 判定正确性 |
| installed | 函数/类真实执行、持久目录跨升级、原生包导入、缺工具节点保留 | 只解析 JSON 就宣布运行通过 |
| perf/extended/gpu | 明确数据规模、真实目标、独立触发；所选 GPU profile 推理与依赖 | 把布尔 busy 当队列数量；把总耗时减最慢工具说成调度耗时 |

核心测试需能解释：什么错误会使它失败。删除低收益测试必须保留关键行为断言，不能仅以减少秒数为目标。算法数值、ROI 逆变换、Owner 延寿、模块销毁、真实打包失败回滚仍应保留。名称先体现领域/行为，再用 test/benchmark 等后缀；不强制全仓统一改名引起大量无效 diff。

正常产品构建不自动跑全套。开发者先构建所需测试组并执行选定 labels；发布候选一次全 CPU；GPU/visual/perf 单列。CTest 的 Passed 必须结合方法级 skip 或拆独立入口解释。没有对应审核实测时不承诺“速度提升 80%”或具体秒数预算。

## R45 新增的最小定向用例

- 新建 → 删除最大已提交id → 保存再打开 → 新增，验证没有复用旧号。
- 交换 id=1/2 的显示顺序，读值、工程 source 和整体输出文本仍按 id 对应。
- inputs0固定，outputs0/1固定，init0合法；逻辑模型不注入上层状态。
- 所有34个token继续可声明；端口别名缺失/重复/更改不影响运行。
- Python {1:...}合法，{"1":...}/True键非法；状态0/1不被宿主补造。
- id很大但仅两个参数时，内存不随最大id线性增长；只做小规模结构检查，无需巨量分配基准。
- expression symbol与id分离，Receiver/Select/helper映射来源正确，复制节点后引用不串参。
- 有旧键映射的声明/工程可转换；缺映射明确报告，保留原文件。迁移仅改端口身份，不改数据载荷。

以上优先放core/SDK/bridge已有测试文件；QML只跑一次完整用户操作链，不为34种类型建34个窗口。维护负例以证明不是“删测后更绿”。
