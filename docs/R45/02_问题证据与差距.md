## 数字编号改造必须覆盖的缺口

| 路径 | R44 基线实现 | R45 目标 |
|---|---|---|
| Contracts Values | map<string, PortValue> | map<PortId, PortValue>，不分配 max(id)+1 个槽位 |
| 参数定义 | PortDefinition.nameEn 承担身份 | PortDefinition.id 承担身份；nameEn 可选说明 |
| 参数读写辅助 | InputReader/OutputWriter 按字符串 | 参数基类、ReadResult 和工具子类按数字 ID；业务仍在工具 |
| Python 边界 | py::dict 字符串端口键 | 输入/输出 dict 整数端口键，信封 outputs/detail 不变 |
| 工程引用 | sourcePort、签名和值以端口字符串标识 | PortId + 既有 flow/node/stage 上下文；持久化为带 port_id 的条目 |
| 关系/智能点选 | PortRef 字符串及字符串 helper 键 | PortRef(stage,id)，输入与 proposal 映射全部数字化 |
| 动态逻辑端口 | 字符串 portId、独立 symbol、nextPortSeq | 数字 portId；保留 symbol 用于 AST，方向分别分配 ID |
| UI 模型 | 行号/字符串上下文 | 参数编号列与稳定选中 ID；排序只移动定义，按 ID 提交 |
| 迁移/部署 | ABI8/schema5/project6 | 提议 ABI9/schema6/project7，一次性转换旧资产并统一发布 |

这些差距说明不能只在 JSON 中加 id 后继续隐藏按 name_en 运行。保留 R44 已修的动态 PythonFactoryResolver 与完整 Array owner，避免迁移时回退。两产品依然通过子模块引用 Contracts/main。
