# R45 完整整合方案：三仓验收整改 + 自定义工具 + 数字参数编号

日期：2026-11-03（Asia/Shanghai）。本包整合 R44 全部验收问题、改进方案与最新已确定的数字编号方案；设计正文、Specs、Tickets、伪代码、示例和原型已统一，旧字符串访问方案不再作为并行目标。

## 已确定的接口

- 端口以稳定数字 `id` 为身份；Python 使用 `inputs[1]`、`outputs[2]`，C++ 参数 Reader/Writer 接受 PortId。
- 端口数组排列只控制 UI 显示顺序。拖动不重编号，新增分配新 ID，已提交删除的 ID 不复用。
- 输入 0 为“上层工具状态”；输出 0/1 为“状态码/状态信息”。固定声明由公共规范化入口注入，不写进工具 JSON；仍在普通参数接口中，由工具解析和包装值。
- Fixed 工具输入业务编号从 1 起；逻辑模型同样保留输入 0，但不因此新增上层状态。输出业务从 2 起；init 独立从 0 起，无固定端口。
- 工具顶层 name_en 继续标识注册工厂；端口 name_en 改为可选说明，不用于取参、绑定、排序或兜底查找。
- 当前载荷、34 种具体类型、所有权、零拷贝、合法性规范、主题、Loop 渲染及已有交互要求继续保留。

## 版本与事实边界

R44 审核的是 RT dev `b0de29c`、Tools dev `e69a2ed`、Contracts main `f9b669a`，实际接口为 ABI8/schema5/project6。R45 提议接口落地时统一升级到 **ABI9/schema6/project7**：因为参数键类型和工程引用真正改变，不再沿用 R44“仅排序无需升级”的结论。若实施时这些版本号已被其他提交使用，应分配下一可用版本号，禁止复用同号表示两种格式。
